### 1. server/index.js
**Vulnerability:** INSECURE_CONFIGURATION  
**Confidence:** HIGH  
**Breaking Changes:** No

**Explanation:** 1. Added Helmet middleware for secure headers. 2. Restricted CORS origins via allowlist loaded from environment. 3. Applied verifyJWT middleware at global protected routes. 4. Centralized error handling to avoid leaking stack traces.

**Security Notes:** Ensure CORS_ORIGINS is set to a comma-separated list of your domains in .env. Always run over HTTPS in production.

**Additional Dependencies:**
- helmet
- cookie-parser

**Testing Recommendations:**
- Attempt CORS requests from allowed and disallowed domains
- Verify secure headers are present via security scanner

### 2. server/controllers/loginController.js
**Vulnerability:** AUTHENTICATION_BYPASS  
**Confidence:** HIGH  
**Breaking Changes:** No

**Explanation:** 1. Added input validation for username/password. 2. Used bcrypt.compare to verify stored hash. 3. Signed JWTs with environment secrets. 4. Issued refresh token in httpOnly, secure cookie with SameSite Strict.

**Security Notes:** Ensure ACCESS_TOKEN_SECRET and REFRESH_TOKEN_SECRET are strong random values and not checked into source control.

**Additional Dependencies:**
- bcrypt
- jsonwebtoken

**Testing Recommendations:**
- Attempt login with invalid credentials, expect 401
- Inspect cookie flags in browser dev tools
